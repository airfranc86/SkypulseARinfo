Problem. metar.py mixes airports, visib parsing, METAR fetch, TAF fetch, Niebla slots and its own UTC-3 clock; metar_observation.py fetches the same AWC METAR URL again, with another cache. Three AWC fetch blocks, each with its own counter.

Solution. One module owns airports, visibility parsing (written once), TAF normalisation, its Niebla projection, observation and ICAO validation, behind one AWC seam.

  • locality: the "6+ means 10 km" rule lives once (today in metar.py:163-177 and taf_decoded.py:101-110)
  • leverage: four callers, one small interface
  • Tests hit one interface with recorded AWC payloads
  • Two adapters justify the seam: HTTP in prod, fixtures in tests
  • Private cross-imports disappear (_validate_icao, _parse_taf_visib_sm)
Repo rule: CLAUDE.md asks for a P0–P3 audit report before any refactor. No ADR conflict.

Problem. Metar.tsx redefines MetarData, hand-rolls the cold-start retry, uses raw fetch; ICAO validation differs in three places; the frontend airport list differs from the backend's by 3 each way (SARP, SANC, SANL vs SAAG, SAMM, SAMR); visNote uses metre cut-offs while the backend uses FAA miles.

Solution. One frontend module (hook plus pure decoding) turns an ICAO into a decoded METAR plus TAF state, reusing the shared retry policy and the backend's decoded TAF.

  • leverage: both pages and the prefill share it
  • Tests become plain imports, not source-text reads
  • TAF reads move off the CheckWX 198/day quota
The decoded-TAF PR for the frontend (FRA-365, in progress) is the first step: it wires /api/taf into Metar.tsx through a new module.
